# Dayflow

A personal daily OS for tasks, focus sessions, and spending — built with React + Vite. Plan your day on the Today view, run Pomodoro sessions in the Focus Room, track income/expenses with budgets, debts, and savings goals, and keep everything local to your device.

It ships two ways from the same codebase:

- **Web / PWA** — installable from Chrome, offline capable.
- **Android APK** — a Capacitor shell with real scheduled notifications that fire with the app closed, plus optional cloud sync.

All data lives in `localStorage` and the app works fully offline. Cloud sync is optional: sign in with email and password and each record syncs through a Supabase database, so the phone and the website stay in step.

## Features

**Tasks**
- Today and Timeline views with a date bar for navigation
- Priorities (low / medium / high / urgent), subtasks, tags, and estimated minutes
- Recurrence: none, daily, weekdays, weekly, monthly, or custom interval
- Per-task reminders with sound selection and snooze
- Quick-add from the floating action button

**Focus Room**
- Pomodoro / short break / long break modes
- Ambient sound option and bell on completion
- Mark a task complete directly from the session

**Categories**
- Custom categories with color and Lucide icon
- Default starter categories included

**Stats**
- Completion and productivity breakdowns across your tasks

**Finance**
- Money Ledger with multiple accounts: cash wallet, savings, current, and other
- Opening balances plus automatically derived account balances (never stored separately)
- Income and expense entries routed to a specific account, with payment method (cash / GPay / PhonePe / bank / card / other)
- Transfers between accounts (including ATM withdrawals with an optional fee), never counted as income or expense
- Account detail screens with credited / debited / transfer totals and running balances
- Ledger history with search, type / account / category / payment / date filters, and day / week / month / year summaries
- Monthly income, expense, net-flow, category and source breakdowns with month-over-month comparison
- Archived accounts keep their history; a migration tool assigns pre-ledger entries
- Recurring transactions (none / daily / weekly / monthly)
- Monthly budgets and per-category budgets
- Debts: track money lent or owed, with paid status
- Savings goals per month
- Bill templates with auto-materialized monthly payments, optionally paid from a chosen account
- Budget alerts at 80% (warning) and 100% (critical)

**App**
- Light / dark theme
- Browser notifications with quiet hours
- Sound effects and speech options
- One device profile for tasks, money, and diary. Optional cloud sync (Supabase, email + password) keeps the website and the phone on the same data
- Undo toast for deletes, JSON export / import, reset to sample data

**Android app**
- Native scheduled reminders (AlarmManager) that survive the app being closed and the phone rebooting
- Per-sound notification channels (chime / bell / digital / gentle / silent) generated from `scripts/generate-notification-sounds.mjs`
- Notification tap opens the right task; in-app banner mirrors the native alert
- Hardware back button closes modals before leaving the app
- Dark splash screen and status bar that follows the theme
- Reminder reliability diagnostics (notification permission, exact alarms, OEM battery tips)
- Optional cloud sync with record-level merge

## Tech Stack

- [React 19](https://react.dev/) with TypeScript
- [Vite 6](https://vitejs.dev/) for dev server and build
- [Tailwind CSS 4](https://tailwindcss.com/) via `@tailwindcss/vite`
- [Lucide React](https://lucide.dev/) for icons
- [Capacitor 8](https://capacitorjs.com/) + `@capacitor/local-notifications`, `app`, `splash-screen`, `status-bar`
- [Supabase](https://supabase.com/) (`@supabase/supabase-js`) for optional sign-in and sync: one Postgres table with row-level security
- `localStorage` for all persistence; no server

## Android app (Google Play)

The `android/` project is generated by Capacitor and committed, so building it
needs no IDE.

One-time prerequisites on this machine:

- Node 22+
- A JDK 21 (Capacitor's notification plugin compiles with Java 21). Point
  Gradle at it with `org.gradle.java.home` in your user-level
  `~/.gradle/gradle.properties` (or set `JAVA_HOME`); the repo does not pin a
  machine path.
- The Android SDK, wired through `android/local.properties` (git-ignored).

### Release build for Play

```bash
npm run release:android   # web build + cap sync + bundleRelease
# -> android/app/build/outputs/bundle/release/app-release.aab
```

The release build is minified and resource-shrunk (R8). Upload
`android/app/build/outputs/mapping/release/mapping.txt` with each release so
Play can de-obfuscate crash reports.

Signing: release builds (`bundleRelease`, `assembleRelease`) read
`android/keystore.properties` (`storeFile`, `storePassword`, `keyAlias`,
`keyPassword`) or, for CI, the environment variables `DAYFLOW_KEYSTORE_FILE`,
`DAYFLOW_KEYSTORE_PASSWORD`, `DAYFLOW_KEY_ALIAS` and `DAYFLOW_KEY_PASSWORD`. If
neither is set the build fails instead of producing an unsigned artifact. Debug
builds need neither.

`dailytasks.keystore` (repo root) and `android/keystore.properties` hold the
key. Both are git-ignored. **Back them up**: with Play App Signing this key is
your upload key, and without Play it is the only key Android accepts for
updates. Its SHA-1 is
`60:BF:C7:3D:F4:C3:BB:E2:16:56:BE:4B:A3:19:C3:BE:B0:46:DA:BE`.

Play Console checklist (manual, not in this repo):

- **Play App Signing**: enrol (Setup -> App integrity).
- **Permission declarations**: `USE_EXACT_ALARM` (alarms and reminders are the
  core feature), `USE_FULL_SCREEN_INTENT` (the alarm ring screen), and the
  `mediaPlayback` foreground service (alarm audio while ringing; Play asks for
  a short video).
- **Data safety**: tasks, finance and diary data stay on the device. With
  optional cloud sync they are also stored in the app's Supabase database
  under the user's account (email address collected for sign-in). Biometrics
  are used only for app lock and never leave the device. No SMS or
  notification access.
- A **privacy policy** URL and the content rating questionnaire.

### Sideload / local testing

```bash
npm run build:android     # vite build --mode capacitor && cap sync android
npm run apk:debug         # android/app/build/outputs/apk/debug/app-debug.apk
npm run apk:release       # signed, minified release APK
npm run apk:install       # adb install -r (device must be connected)
```

Without a cable, copy `android/app/build/outputs/apk/release/app-release.apk`
to the phone and allow "Install unknown apps" for the file manager.

Notification sounds are generated once into
`android/app/src/main/res/raw/*.wav`. Re-run
`node scripts/generate-notification-sounds.mjs` if you want to tweak them.

Each task's chime choice maps to its own notification channel
(`reminders_chime`, `reminders_bell`, `reminders_digital`, `reminders_gentle`,
plus `reminders_silent` when in-app sound is off). Two Android constraints to be
aware of:

- Channel settings are immutable once created, so changing a task's sound takes
  effect on its next scheduled reminder, and Android remembers per-channel sound
  overrides the user made in system settings.
- A notification channel cannot run text-to-speech, so the `voice` option falls
  back to the chime channel on Android. The in-app banner still shows the task.

Bumping a release: raise `versionCode` (every Play upload needs a higher one)
and `versionName` in `android/app/build.gradle`, keep `version` in
`package.json` in step, then rebuild.

### Bank spends from notifications (not on main)

Reading bank spends from messaging-app notifications needs an Android
notification listener, which Play does not allow for an app like this and which
Play Protect blocks when sideloaded. It is kept on the
`feature/bank-sms-notifications` branch for personal, USB-installed builds. On
`main` the native listener is removed and the Finance inbox is hidden behind
`VITE_ENABLE_BANK_SMS` (off). Spends already confirmed from it are ordinary
ledger entries and are unaffected.

## Environment

See [`.env.example`](.env.example).

| Variable | Required | Purpose |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | No | Supabase project URL. Needed only for cloud sync |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | No | Supabase publishable (or legacy anon) key. Public by design; row-level security protects the data |
| `VITE_ENABLE_BANK_SMS` | No | `"true"` shows the bank-spend inbox. Leave off on `main`: it needs the native listener from `feature/bank-sms-notifications` |

Everything else works without environment variables. Never put the Supabase
`service_role` / secret key in `.env` or anywhere in the app.

### Cloud sync setup (Supabase)

1. Supabase dashboard -> your project -> **Connect** -> **Framework** -> React.
   Copy the project URL and publishable key into `.env` (and into the host's
   build variables, e.g. Vercel).
2. **SQL Editor** -> run
   [`supabase/migrations/20261114120000_dayflow_records.sql`](supabase/migrations/20261114120000_dayflow_records.sql)
   once. It creates `public.dayflow_records`, the last-write-wins trigger, the
   grants for signed-in users and the row-level security policies. Running it
   again is safe.
3. **Authentication -> URL Configuration**: set the Site URL to the deployed
   site (`https://daily-tasks-management.vercel.app`) and add it and
   `http://localhost:3000` to the redirect URLs. The email confirmation link
   returns there.
4. Rebuild. In the app: Settings -> Cloud Sync -> Create account, confirm the
   email, then Sign in. The first sign-in uploads what is on the device.

How it works: every record is one row, keyed by its id, with the record's own
`updatedAt`. A deleted record is a row with `deleted = true`. The newer
`updatedAt` wins both in the app merge and in a database trigger, so two devices
pushing at once can never move the server backwards. Devices pull only rows
changed since their last sync (ids first, full rows only when newer), and push
only records saved since their last push. Each device keeps a full local copy
and works offline.

### Cloud sync troubleshooting

Settings -> Cloud Sync -> **Test connection** checks setup, account and
database access, and names the step that fails.

| Symptom | Cause |
| --- | --- |
| "The dayflow_records table is missing" | The migration has not been run in the SQL editor |
| "Signed-in users can't use dayflow_records" | The grants are missing; run the migration again |
| "Confirm your email first" | The confirmation link has not been opened yet |
| "Can't reach Supabase" | No connection, or the network blocks `supabase.co` (see below) |
| "This device is linked to another account" | Sign out, then sign in with the other account; the app asks before replacing this device's data |

Some Indian networks block `*.supabase.co` by DNS (a MeitY order); the browser
shows a page that says the website has been blocked. A device using encrypted
DNS (Chrome Secure DNS, Android Private DNS) is not affected.

## Data and Privacy

- All data is stored in `localStorage` on this device, under one set of keys. There is no local account.
- Cloud sync is optional and off until you sign in. Desktop and phone stay in sync by signing in to the same account. Sync now merges; Restore replaces this device and drops edits that were never uploaded.
- Synced data is stored in the app's Supabase database. Row-level security limits every row to the account that owns it; signed-out requests get no access at all.
- Clearing app/browser storage erases the data on that device. Sign in again (or use Export JSON) to get it back.
- Sync is last-write-wins per record, with deletes tracked as tombstones. An open browser tab pulls changes when it regains focus, comes back online, and once a minute while visible; the Android app pulls when it comes to the foreground.
- Signing out leaves the data on the device. Signing in with a different account asks before replacing this device's data, so two accounts are never merged.
